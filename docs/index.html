bhejo — send

Send a file to the computer next to you.

Peer-to-peer over your local network. No cloud, no accounts, no upload quota, no dependencies. Your files never leave the room, and they arrive byte for byte identical.

The interface

One page, served by the receiver on 127.0.0.1 — it never leaves your machine.

What it does differently

01

Nothing in the middle

Two machines open a socket to each other. No server to trust, no account to create, no file sitting on someone else's disk.

02

Encrypted, and pinned

TLS with a real certificate, checked against the fingerprint the other machine prints. Trust on first use, remembered after that.

03

Verified on arrival

The receiver hashes while it writes. Both sides compare SHA-256 at the end. A mismatch is a failure, not a warning.

04

Original quality

Bytes are copied as they are. No re-encoding, no resizing, no "optimising" your photos on the way through.

05

Whole folders

Drop a directory and the structure is walked recursively, then rebuilt on the other side the same way.

06

Optional PIN

Make people prove they are in the room. Auto-accept mode generates one for you unless you say otherwise.

How it works

  1. ReceiveOne machine starts a receiver and announces itself over multicast.
  2. DiscoverThe other lists nearby devices and picks one by name or address.
  3. Confirm onceFirst contact shows a certificate fingerprint to compare out loud.
  4. StreamThe file goes over TLS in one prepare-then-upload handshake, hashed as it lands.

Discovery is a multicast beacon on the local subnet — no central registry, no cloud lookup, no domain to resolve. If two machines are on the same network, they can see each other. If they are not, they cannot.

Quick start

You need Node.js 18.17 or newer. That is the whole list — there is nothing to install. 

git clone https://github.com/rushi0105/bhejo.git
cd bhejo

# machine A: wait for something to arrive
node bin/bhejo.mjs receive

# machine B: see who is nearby, then send
node bin/bhejo.mjs discover
node bin/bhejo.mjs send ./report.pdf --to Kitchen-PC

Open http://127.0.0.1:53318 on the receiving machine for the browser UI. Run npm link once if you would rather type bhejo.

Honest limitations

  • No resume — an interrupted transfer starts again.
  • One file at a time, sent in sequence.
  • No iOS client. Android works under Termux.
  • IPv4 only, and the browser UI is local to the receiving machine by design.
  • Terminal first. There is no installer, tray icon or auto-update.
