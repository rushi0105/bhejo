One page, served by the receiver on 127.0.0.1 — it never leaves your machine.

Nothing in the middle.

Two machines open a socket to each other. There is no server to trust, no account to create, and no copy of your file on someone else’s disk.

Transport

Encrypted, and pinned

A real TLS certificate, checked against the fingerprint the other machine prints. Trust on first use, remembered after that.

Integrity

Verified on arrival

The receiver hashes while it writes. Both sides compare SHA-256 at the end, so a mismatch is a failure rather than a warning.

Fidelity

Original quality

Bytes are copied as they are. No re-encoding, no resizing, no “optimising” your photos on the way through.

Folders

Whole directories

Drop a folder and the tree is walked recursively, then rebuilt on the other side exactly the same way.

Access

Optional PIN

Make people prove they are in the room. Auto-accept mode generates a PIN for you unless you say otherwise.

Setup

Nothing to install

Node 18.17 and the standard library. No npm install, no build step, no node_modules to audit.

Four steps, once.

After the first pairing, sending a file is two commands.

01

Receive

One machine starts a receiver and announces itself over multicast.

02

Discover

The other lists nearby devices and picks one by name or address.

03

Confirm once

First contact shows a certificate fingerprint to compare out loud.

04

Stream

The file goes over TLS in one prepare-then-upload handshake, hashed as it lands.

Discovery is a multicast beacon on the local subnet — no central registry, no cloud lookup, no domain to resolve. If two machines are on the same network they can see each other. If they are not, they cannot.

Two commands.

You need Node.js 18.17 or newer. That is the whole list.

$ git clone https://github.com/rushi0105/bhejo.git
$ cd bhejo

# machine A — wait for something to arrive
$ node bin/bhejo.mjs receive

# machine B — find it, then send
$ node bin/bhejo.mjs discover
$ node bin/bhejo.mjs send ./report.pdf --to Kitchen-PC

Open http://127.0.0.1:53318 on the receiving machine for the browser interface. Run npm link once if you would rather type bhejo.

What it doesn’t do.

Every project should say this out loud.

No resume. An interrupted transfer starts that file again from zero.
Sequential uploads. One file at a time, never in parallel.
No mobile app. iOS has no supported path; Android works under Termux.
IPv4 only. The browser UI stays local to the receiving machine.
Terminal first. No installer, no tray icon, no auto-update.
LAN only. Different networks need a tunnel; this is not one.
